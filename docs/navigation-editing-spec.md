# 1区・2区 ナビゲーション編集機能 仕様

最終更新: 2026-05-14
決定方法: grill-me で論点を1つずつ詰めて確定

## 目的

スライド作業場の1区（全体ナビ）と2区（セクション一覧）に並ぶタイトル類を、ユーザーがUIから追加・編集・削除できるようにする。これまで `SALES_SECTIONS` 配列および contentTheme で**ハードコード**されていた章名・プロジェクト名を、ユーザーの作業対象（販売スライド以外も）に合わせて自由に組み替えられるようにするのが狙い。

## 階層構造

```
大テーマ（2個固定・不動）
├─ 講義スライド
│   └─ 小テーマ (ユーザーが任意に追加)
│       └─ 章 (ユーザーが任意に追加)
└─ ブートキャンプ
    └─ 小テーマ
        └─ 章
```

### 大テーマ

- 「講義スライド」「ブートキャンプ」の **2個固定**
- **追加・削除・名前編集すべて不可**。ソースコード上の定数として扱う
- 1区のテーマ選択UIはそのまま流用（contentTheme: "lecture" | "bootcamp"）

### 小テーマ

- 各大テーマの配下に、ユーザーが任意の数だけ作れる
- **追加・編集・削除すべて可能**
- 1個も小テーマがない大テーマでは、2区は空の状態を表示する

### 章

- 各小テーマの配下に、ユーザーが任意の数だけ作れる
- **追加・編集・削除すべて可能**
- 並び替え（D&D）は今回スコープ外

## 既存データの移行

既存の `SALES_SECTIONS`（10章ハードコード）と CHAPTER_DEFAULTS（章別原稿）、editedScripts、workspaceV2State、generatedSlidesBySection は、`bootcamp` 大テーマ配下の **「Claude Codeブートキャンプ販売スライド」** という小テーマに紐づける形で初期データとして移行する。

- 既存ユーザー（自分）の作業状態（採用済みスライド・編集中原稿）はそのまま継続する
- `lecture` 大テーマには初期小テーマを置かない（ユーザーが追加するまで空）

## 2区ヘッダ表示

選択中の **「大テーマ / 小テーマ」** を同じ行にスラッシュで区切って表示する。

例:

```
ブートキャンプ / Claude Codeブートキャンプ販売スライド
```

## UI

### 編集（小テーマ／章タイトル）

- タイトル行にホバーすると右端に **鉛筆アイコン** が現れる
- 鉛筆をクリックするとタイトル部分がその場で `<input>` に変わる
- `Enter` で確定、`Esc` で破棄
- 空欄のまま確定しようとした場合は元の値に戻す（保存しない）

### 追加

- 小テーマ追加: 1区で大テーマを選んでいる状態で「+ 小テーマを追加」ボタン
- 章追加: 2区の章リストの末尾に「+ 章を追加」ボタン

追加直後はインライン input にフォーカスし、タイトルをすぐ編集できる状態にする。

### 小テーマを追加したときの初期章

- 空のタイトル `1. 新しい章` を持つ章1個を自動で作成する（空原稿）
- 「画面に何も無い」状態を避け、すぐ作業に入れる動線にするため

### 削除

章・小テーマのいずれも、削除ボタン押下時に **確認ダイアログ** を表示する：

> 「この章（小テーマ）を削除すると、原稿・採用状態・生成スライドのメタ情報も消えます。続けますか？」

確認したら一括削除する。

**削除されるもの**

- 章ID / 小テーマID とそのタイトル
- `editedScripts[章ID]`（原稿）
- `workspaceV2State.sections[章ID]`（段落設定・採用フラグ・slideHistory）
- `generatedSlidesBySection[章ID]`（生成スライドのメタ）
- `selectedGeneratedSlidesBySection[章ID]` などの選択状態

**削除されないもの**

- `public/regenerated/<timestamp>/*.png`（実ファイル本体）。後でクリーンアップしたい場合は別途バッチで消す方針

## データモデル

### 永続化先

既存の `workspace-state-v2` API を拡張し、トップに `navigation` フィールドを追加する。

```ts
type WorkspaceV2State = {
  navigation: {
    themes: Record<"lecture" | "bootcamp", {
      subThemes: Array<{
        id: string;                // 小テーマID（連番 or 安全な一意ID）
        name: string;              // 小テーマ名
        chapters: Array<{
          id: number;              // 章ID（パラグラフID生成等で使う既存数値ID）
          title: string;           // 章タイトル
        }>;
      }>;
    }>;
  };
  sections: Record<number, WorkspaceV2SectionState>;  // 既存
};
```

### 章ID

既存のparagraphId生成 (`createParagraphId(sectionId, block)`) で**数値ID**として使われているため、章IDは引き続き **number**（連番）で管理する。新しく章を作るときは「全テーマ・全章を通じての最大ID + 1」を採番する。

### 小テーマID

小テーマには段落IDのような外部参照がないので、文字列 (`sub-${timestamp}` のような形式) で十分。

## バリデーション

- **空欄禁止のみ**
- 重複名・文字数上限はチェックしない（運用負荷の方が大きいため）
- 空欄のまま確定しようとした場合は何もせず編集前の値に戻す（保存しない）

## 既存機能との整合性

- **キャレット↔右ペイン連動**: 章ID単位で動くので変更なし
- **採用機能**: paragraphId に章IDを含むので、章を削除すると採用情報も自然に消える
- **2区カウント**: `computeSectionProgress` は章ID単位なので章増減に追従。ヘッダの「全体 N/M枚」は全章合計でそのまま動く
- **ZIPダウンロード**: 全章採用済み判定で動いている。新規追加した章で未採用が出るとボタンが無効化される

## 未決事項

実装時に決める軽い項目：

- 「+ 章を追加」「+ 小テーマを追加」ボタンの具体的なスタイルと位置（章リスト末尾／大テーマ展開リスト末尾を想定）
- ホバーが効かないタッチデバイスでの編集導線（当面 PC のみ想定で省略可）
- 並び替え（D&D）は今回スコープ外、必要になったら追加実装

## 出典

仕様は2026-05-14のgrill-meセッションで確定。決定の依存順は次の通り：

1. 編集スコープ → 章タイトル＋プロジェクト名
2. 操作範囲 → CRUD（並び替えは除外）
3. プロジェクト名の編集方法 → 1区テーマで階層化する方式へ転換（大テーマ⊃小テーマ⊃章）
4. 大テーマ → 完全不動
5. 小テーマ → CRUD
6. 既存データ移行 → bootcamp配下に1つ小テーマを作って移行
7. 2区ヘッダ → スラッシュ区切り
8. 小テーマ追加時の初期章 → 空1章
9. 削除挙動 → 確認ダイアログ＋一括削除
10. 編集UI → 鉛筆＋インラインinput
11. 保存先 → workspace-state-v2拡張、空欄禁止のみ
