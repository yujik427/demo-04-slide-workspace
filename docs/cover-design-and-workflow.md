# 表紙キービジュアル — デザイン仕様 & ワークフロー

> アドネス採用評価タスク（CCブートキャンプ販売スライド自動生成システム）の **提出物② デザイン&ワークフロー言語化ドキュメント** の下書き。
> grill-me で詰めた 2026-05-14 時点の決定事項を起こしたもの。

## 1. 目的

「Claude Code ブートキャンプ販売スライド」の **1枚目(表紙)** を、スキルプラス講座サムネ級の完成度で、ワークスペース(localhost:3000)上で **再現性高く** 量産できるようにする。

「再現性高く」= 同じ手順で誰がやっても同じ品質に到達する。AI生成のブレに依存しない。

## 4. 自動化レベル & 役割分担

**方針**: テンプレート型 + AIを「裏方」に配置する。

人が判断するポイントを残すことで「センス」評価軸を確保しつつ、AIは複数レイヤーで裏方として働く=「AI活用力」評価軸も確保。

| ステップ | AI担当 | 人担当 |
|---|---|---|
| キャッチ帯文言案 | **3案を生成** | 1案を選ぶ |
| キャラ画像 | **事前に複数バリエ生成しライブラリ化** | ライブラリから選ぶ |
| 配色 | プリセット提案 | クリックで切替 |
| 構図・レイアウト | (固定テンプレ) | (変更不可) |
| 画像化(HTML→PNG) | **Playwrightで自動** | — |
| 最終品質チェック | — | 目視確認 |

## 5. ワークフロー(工程の流れ)

### Phase 0: 準備(1回だけ)

| # | 作業 | 担当 |
|---|---|---|
| 0-1 | 表紙HTMLテンプレート(Reactコンポーネント)を実装 | 開発者(Claude Code) |
| 0-2 | キャラ画像ライブラリを事前生成(スキルプラス調人物 × 数バリエ + Clawd素材) | AI画像生成 |
| 0-3 | ワークスペース右ペインに「表紙生成」セクションを追加 | 開発者 |
| 0-4 | キャッチ帯文言の3案生成ロジック(Claude API)を実装 | 開発者 |

### Phase 1: 表紙1枚を作る(毎回の作業 / 想定3分)

| # | 操作 | ペイン | 担当 |
|---|---|---|---|
| 1-1 | テーマ「Claude Code ブートキャンプ販売スライド」を選択 | 左端 | 人 |
| 1-2 | スライド1(表紙)を選択 | 左 | 人 |
| 1-3 | 「キャッチ帯3案生成」ボタンを押す → AIが3案表示 | 中央 | AI→人 |
| 1-4 | 3案から1つ選ぶ(または微修正) | 中央 | 人 |
| 1-5 | キャラライブラリから1つ選ぶ | 右 | 人 |
| 1-6 | 配色プリセットから1つ選ぶ | 右 | 人 |
| 1-7 | 「この条件で1枚生成」ボタン押下 | 右 | 人 |
| 1-8 | Playwright が HTMLレンダリング → PNG出力 | 裏側 | AI |
| 1-9 | プレビュー表示 → 品質確認 | 右 | 人 |
| 1-10 | 必要なら設定変えて再生成、OKならダウンロード | 右 | 人 |

### Phase 2: バリエ展開(複数バリエーション提出のため)

- キャラを変える → 再生成(数秒で別バリエ)
- 配色を変える → 再生成
- キャッチ帯文言を変える → 再生成

→ **同じ手順で複数バリエが出る = 再現性 + バリエ提出要件を満たす**

## 6. 採用評価軸への対応

| 評価項目 | 本ワークフローでの対応 |
|---|---|
| **AI活用力** | AIが ①キャッチ帯3案生成 ②キャラ事前バリエ生成 ③HTML→PNG自動化 の3レイヤーで裏方として働く |
| **スピード** | テンプレ型のため、パラメータ変更で数秒。複数バリエ即時 |
| **クオリティ** | スキルプラスの参照水準 + HTML/CSSで再現性確保(AI画像生成の文字崩れ等を回避) |
| **センス** | 数字+結論型キャッチ、ダーク×黄色帯のトーン整合、レイアウトはスキルプラス踏襲 |
| **コミュニケーション** | 本ドキュメントで言語化 + grill-me による対話型決定プロセス |
| **再現性** | テンプレ + パラメータ化。誰が・何回やっても同じ手順で同じ品質に到達 |

## 9. 注意事項

- **2026-05-14調査結果: Clawd は Anthropic 公式マスコット(ピクセルクラブ)で商用利用には許諾必要**。Jobs(CEO)はリスク回避のためオリジナル雲ロボを推奨したが、オーナー最終判断によりClawdインスパイア型を採用。フラグ等の固有要素の完全模倣は避け、配色・形状のスタイルだけ踏襲する範囲で実装する
- **AI生成キャラは「ライブラリ化(事前生成)」が原則**。毎回生成するとブレて再現性評価で減点
- **テンプレートのレイアウトは絶対に動かさない**。動かすとテンプレ型の意味がない=採用評価の「再現性」を捨てることになる
