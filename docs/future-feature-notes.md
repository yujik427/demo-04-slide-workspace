# 将来機能メモ

作成日: 2026-05-12  
目的: 実装時にすぐ引けるよう、現時点で共有された機能イメージを記録する。

## 前提

このメモは、まだ実装しない。  
現時点では、4ペインHTML図解と今後の実装判断のための参照資料として残す。

アプリの主役は、スライドを1枚ずつ手で作ることではない。  
原稿を書く、章立てを見る、スライド候補を指定する、画像素材を用意する、保存・書き出しにつなげる、という一連の制作工程を同じ作業場で扱う。

## 4ペインの基本構成

| ペイン | 役割 | 手動最小化の効き目 |
|---|---|---|
| 1. 左: 全体ナビ | カリキュラム / 講義一覧を階層で表示する | 迷子にならない。他講義との往復が一発でできる |
| 2. 中央左: セクション一覧 | 章立て、進捗、目標枚数と実績枚数を表示する | 全体の歪みが一目でわかる |
| 3. 中央: 原稿エディタ | 段落単位で本文を書く。文字数を表示する | スライドではなく「話す内容」を書くだけに集中できる |
| 4. 右: スライド / メディア | スライド候補プレビュー、画像素材、テンプレート、差し込みを扱う | 素材探しやスライド確認の往復を減らせる |

## 1. 原稿を書く機能

中央ペインで、段落単位に原稿を書く。

- Enterキーで段落を追加する
- 1段落ごとに文字数を表示する
- 原稿は「話す内容」であり、スライド文面そのものではない
- スライドの見た目や画像探しは右ペインに寄せる
- 原稿執筆中に、講義全体や章の位置を見失わないようにする

実装時の注意:

- 原稿エディタをスライド編集画面にしない
- 1段落 = 1候補素材に変換しやすいデータ構造にする
- 段落追加、段落分割、段落削除を後から扱えるようにする

## 2. スライドを指定する機能

右ペインで、原稿段落やセクションに対してスライド候補を指定する。

- 原稿段落からスライド候補を作る
- 既存テンプレートから使うスライド型を選ぶ
- 候補スライドを追加する
- どの原稿段落が、どのスライド候補に対応するか見えるようにする
- 完成確認ではなく、まずは「どのスライドにするか」を決める場所にする

実装時の注意:

- 右ペインを最終編集だけの場所にしない
- テンプレート選択、候補追加、候補差し替えを同じ導線で扱う
- 1枚だけ再生成できる余地を残す

## 3. スライドに画像を入れる機能

右ペインで、スライドに入れる画像素材を扱う。

- 画像説明を入力する
- 画像を生成する
- ライブラリから選ぶ
- ファイルをアップロードする
- Web検索から候補を探す
- 生成された画像候補から採用するものを選ぶ
- 採用した画像をスライド候補に反映する

実装時の注意:

- 画像生成は初期MVPでは入口だけでよい
- 画像説明はスライドごとに保存できるようにする
- 画像候補は複数持てるようにする
- 「採用」「未採用」「差し替え」を状態として持つ

## 4. バージョンを保存する機能

作業状態を保存し、確認・プロンプター・書き出し・記録へつなげる。

- 保存済み時刻を表示する
- 確認モードに切り替える
- プロンプター表示に切り替える
- 書き出しを行う
- 記録として残す
- 途中状態の復元を可能にする

実装時の注意:

- 初期MVPでは本格的なバージョン管理は作らない
- ただし、将来のために `version` や `snapshot` の概念は設計に残す
- 保存対象は原稿だけでなく、スライド候補、画像候補、採用状態も含める

## 5. 情報はデータベース管理

原稿、スライド、画像、バージョンはデータベース管理を前提にする。

想定する主要データ:

- カリキュラム
- 講義
- セクション
- 原稿段落
- スライド候補
- スライドテンプレート
- 画像説明
- 画像候補
- 採用済み画像
- バージョン / スナップショット

実装時の注意:

- 初期MVPではローカルJSONでよい
- ただし、DBへ移しやすい粒度でデータを分ける
- 原稿とスライドと画像を1つの巨大JSONに潰さない
- 複数画面、書き出し、記録から同じ情報を参照できる構造にする

## 実装時に守ること

- まずHTML図解で画面意図を確認する
- 画面をコピー編集専用に寄せない
- 中央は「原稿を書く場所」、右は「候補と素材を扱う場所」として分ける
- 最終的な完成確認は大プレビューや確認モードに逃がす
- 初期MVPでは、ログイン、複数ユーザー、本格DB、外部連携は作らない
